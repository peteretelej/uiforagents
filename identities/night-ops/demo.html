01 · design rationale

Why the console looks the way it looks.

decisions, not options

night-ops exists so an agent building an ops artifact stops making dashboard decisions and starts shipping one. The dark ground is the product: ops consoles are watched for hours in dim rooms, phosphor-cool hue 255 keeps long sessions calm, and elevation is expressed by hairlines and luminance steps - never shadows, which belong to the four floating layers only (tooltip, modal, toast, palette).

Color is disciplined to two jobs. Azure is the instrument voice: live series, active controls, the one primary action. Green, amber, and red are a status vocabulary that only ever encodes real state - an LED, a lifecycle chip, a semantic delta, a threshold fill. A number going up is not good or bad by itself, so deltas are semantic (.no-pos/.no-neg/.no-neu) and always name their comparison window: ▲ on an error rate reads red.

Density comes from alignment, not shrinkage: mono tabular figures for every numeral, 10px tracked uppercase mono labels, hairline row rules, and 1px-gap grids where the rule shows through the seams. Type never drops below 9px (status chips), and charts stay hand-authored SVG so any artifact prints and renders with zero JavaScript.

10 · themes & print

Dark leads. The light scheme is the derived alternative - the same tokens re-resolved, re-gated for AA. Print performs the same flip in one line, and motion dies under reduced-motion and in print.

print contract

@media print
· The scheme flip re-inks every panel, chip, chart and LED for paper - nothing is hand-recolored.
· Chrome hides: filters, tools, action buttons, palette stages (.no-print).
· Panels, KPI strips and tables never split across pages (break-inside: avoid).
· Pulse, shimmer, transitions and floating shadows are disabled; hairlines carry all structure.

theme toggle

the only sanctioned JS
· One click flips html.style.colorScheme between dark and light; every token re-resolves.
· The page renders fully with the script removed - the toggle is a convenience, never a dependency.
· No class swapping, no duplicate token lists, no data-theme attributes.
